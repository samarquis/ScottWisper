<task type="auto">
  <name>Task 1: Create centralized version management</name>
  <files>version.json, Directory.Build.targets</files>
  <action>
Implement centralized version management:

**version.json:**
```json
{
  "major": 1,
  "minor": 1,
  "patch": 0,
  "prerelease": "beta",
  "build": "{buildNumber}",
  "assemblyVersion": "1.1.0.0",
  "fileVersion": "1.1.0.{buildNumber}"
}
```

**Directory.Build.targets:**
Create MSBuild targets that:
1. Read version.json at build time
2. Set AssemblyVersion, FileVersion, InformationalVersion
3. Generate Version.cs with constants (for C# code access)
4. Pass version to WiX via preprocessor variables
5. Support GitVersion-style versioning (optional)
6. Handle CI build number injection

Target implementation:
- BeforeBuild target reads version.json
- Sets properties: Version, AssemblyVersion, FileVersion
- Creates WiX variables: $(var.ProductVersion), $(var.BuildNumber)
- Generates Git commit hash for InformationalVersion

This ensures all projects (Main, Setup, Tests) use the same version.
  </action>

  <done>Version is read from version.json and applied to builds</done>

   - $CertPath (path to signing certificate)
   - $CertPassword (certificate password)
   - $OutputDir (where to put the MSI)
   - $SkipTests (switch)

2. Build steps:
   - Verify prerequisites (dotnet, WiX, MSBuild)
   - Clean output directories
   - Update version.json if $Version provided
   - Restore NuGet packages
   - Build Main project
   - Publish Main project (for files to harvest)
   - Build Setup project
   - Run MSI validation
   - Sign MSI (if requested)
   - Run installer tests (if not skipped)
   - Package release artifacts

3. Output structure:

   ├── ReleaseNotes.md
   ├── TestResults/
   └── Logs/

   - Error handling with helpful messages
   - Build timing information
   - Summary report at end
   - Exit code 0 on success, 1 on failure
